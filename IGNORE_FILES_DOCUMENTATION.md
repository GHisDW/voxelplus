# .gitignore Documentation — Voxel⁺ Launcher

This document provides a detailed breakdown of all entries in the repository's `.gitignore` file. It explains what each category contains, why it is ignored, whether it can contain user data, whether it is safe to delete, whether it is regenerated automatically, and any development implications.

---

## 1. Dependencies

### `node_modules/`
* **Contains**: Third-party Node.js packages installed via `npm install`.
* **Why Ignored**: Dependencies are managed by `package.json` and `package-lock.json`. Committing `node_modules` bloats the repository.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, automatically by running `npm install`.
* **Commit to Repo**: Never.

### `package-lock.json`
* **Contains**: Exact version tree and checksums of installed Node dependencies.
* **Why Ignored in .gitignore**: In this repository, `package-lock.json` is explicitly listed in `.gitignore` to allow flexible dev environment package resolution across platforms.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, generated when running `npm install`.
* **Commit to Repo**: No.

---

## 2. Build Outputs

### `dist/`
* **Contains**: Bundled frontend production assets output by Vite.
* **Why Ignored**: Compiled production artifact created during `npm run build`.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, by running `npm run build` or `vite build`.
* **Commit to Repo**: Never.

### `dist-electron/`
* **Contains**: Compiled TypeScript output from Electron main and preload scripts (`main.js`, `preload.js`, etc.).
* **Why Ignored**: Compiled build artifact generated from source TypeScript files in `electron/`.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, by running `npm run build` or `tsc -p electron/tsconfig.json`.
* **Commit to Repo**: Never.

### `*.js` / `*.js.map` / `*.d.ts` (Except `!electron/types.ts`)
* **Contains**: Transpiled JavaScript files, source maps, and declaration files generated by TypeScript in source folders.
* **Why Ignored**: Keeps source directories clean from transient transpilation artifacts. `electron/types.ts` is explicitly preserved as it is a hand-written source type file.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, by the TypeScript compiler.
* **Commit to Repo**: Never (except source files like `electron/types.ts`).

---

## 3. Environment Files

### `.env` / `.env.local` / `.env.*.local`
* **Contains**: Environment variables and local configuration settings (e.g. API endpoints, port numbers).
* **Why Ignored**: Prevents sensitive local machine or environment credentials from being committed.
* **Contains User Data**: May contain local configuration or API keys.
* **Safe to Delete**: Yes, but local environment settings will need to be re-entered.
* **Regenerated**: No, created manually by developers if required.
* **Commit to Repo**: Never.

---

## 4. Logs

### `logs/` / `*.log` / `npm-debug.log*` / `yarn-debug.log*` / `yarn-error.log*`
* **Contains**: Application run logs, crash reports, and package manager debugging logs.
* **Why Ignored**: Machine-specific runtime information and diagnostic data.
* **Contains User Data**: May contain local paths or runtime diagnostics.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, generated during application runtime or debugging sessions.
* **Commit to Repo**: Never.

---

## 5. OS System Files

### `.DS_Store` / `Thumbs.db` / `desktop.ini`
* **Contains**: Operating system metadata (macOS Finder view settings, Windows thumbnail caches).
* **Why Ignored**: OS-specific metadata files that have no relevance to the application source code.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, by macOS Finder or Windows Explorer.
* **Commit to Repo**: Never.

---

## 6. IDE & Editor Files

### `.vscode/` / `.idea/` / `*.swp` / `*.swo` / `*~`
* **Contains**: VS Code settings, IntelliJ/WebStorm project files, and Vim swap files.
* **Why Ignored**: Developer-specific IDE preferences and temporary editor buffers.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, by the respective editor.
* **Commit to Repo**: Never.

---

## 7. Test Data

### `test-instances/` / `test-gradle-env/` / `test-runclient-env/` / `test-e2e-data/`
* **Contains**: Temporary Minecraft instances, test Gradle builds, and end-to-end testing directories created during local development tests.
* **Why Ignored**: Transient test artifacts and development environments.
* **Contains User Data**: May contain temporary local test instances.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, during local test execution.
* **Commit to Repo**: Never.

---

## 8. Temporary Files

### `*.tmp` / `*.temp` / `.cache/`
* **Contains**: Temporary cache buffers and scratch files created during file operations or downloads.
* **Why Ignored**: Prevents unneeded transient files from entering source control.
* **Contains User Data**: Transient cache data.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, during build or file processing.
* **Commit to Repo**: Never.

---

## 9. Electron Executable Outputs

### `out/` / `*.app` / `*.dmg` / `*.exe` / `*.deb` / `*.rpm`
* **Contains**: Packaged native desktop executables and installers generated by Electron Builder or Electron Forge.
* **Why Ignored**: Binary installer artifacts compiled for target distribution operating systems.
* **Contains User Data**: No.
* **Safe to Delete**: Yes.
* **Regenerated**: Yes, by running native application packaging commands.
* **Commit to Repo**: Never.
